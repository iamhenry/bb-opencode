## Current path

- The app registers one global BB message action in `app.tsx:48-60`, with `icon: "Undo2"` at line 51. Its callback forwards `message.id`, `message.role`, and `message.text` to `runMessageUndo`.
- `src/app/message-revert.ts:4-24` calls plugin RPC `undo` with `messageId`, role, and text. `server.ts:630-636` receives that BB message id as `bbMessageId` and calls `revertThread`.
- `server.ts:1682-1742` confirms the session is settled, stops/waits for the BB turn, gets hidden BB rows from the clicked row id, then calls host RPC `revert`. This avoids projecting an unrelated BB suffix, but it does not turn the BB id into an OpenCode id.
- `src/host-handlers.ts:247-269` reads the OpenCode history and calls `resolveRevertMessageId`. `src/revert-target.ts:36-70` prefers exact `messageID` if supplied, otherwise matches role/text, then fuzzy text; duplicate exact matches fail closed. The current action-to-host flow sends `messageId`, not an OpenCode `messageID`, so duplicate prompt text remains ambiguous.
- **The ticket’s “v1 one-shot revert” description is stale for this candidate.** `src/client.ts:417-423` already calls `sdk.session.revert.stage` and `.clear`, through the existing `OpenCodeClient.revert`/`unrevert` adapter. The package pins `@opencode/client` `^2.0.18` (`package.json:31-34`). There is no commit method in `OpenCodeClient` or these adapter methods.
- Host-side RPC contracts are in `contract.ts:128-145`; UI-to-server RPC contracts are in `contract.ts:362-385`. The existing dock's undo action sends `redo`, which routes to host `unrevert` and therefore v2 clear (`src/app/revert-dock.tsx:136-155`, `server.ts:638-639`). The dock currently calls the action **“Undo revert”** and has no explicit Commit button (`src/app/revert-dock.tsx:157-194`).
- `src/host-handlers.ts:214-230` aborts a running OpenCode session and polls until it settles. `server.ts:1658-1679` also waits for the BB thread to become idle/error before mutating history.

## State, timeline, events, and composer

- OpenCode session reads preserve `session.revert`: `src/v2-map.ts:333-355` adapts it, and `src/hydrate.ts:30-45` extracts the revert cursor and excludes the target and later provider messages during hydration.
- V2 revert events are translated to generic `session.updated` in `src/v2-map.ts:314-319`. `src/client.ts:317-322` translates the SSE stream; `src/bridge.ts:1735-1757` reacts to the update and calls `syncSessionRevert`, which rereads `session.revert` (`src/bridge.ts:1242-1258`). The event payload itself is not projected as a detailed revert state into BB.
- The app obtains richer state through host `revertState` (`server.ts:641-678`, `src/host-handlers.ts:280-291`). It returns the target prompt and hidden user-message previews. The dock refreshes on plugin realtime updates and polls every 800 ms while active (`src/app/revert-dock.tsx:67-110`). The app timeline content script applies `data-oc-reverted` to rows from the projection (`src/app/revert-timeline.ts:29-36, 45-108`).
- The dock saves only the previous plain-text draft in `sessionStorage`, writes the target prompt with `composer.setText`, and restores that previous text on clear (`src/app/revert-dock.tsx:21-49, 112-155`). BB's SDK `useComposer` API supports reading text, setting text, focusing, and locking; `setText` preserves independently attached files (installed SDK 0.4.16 `bundled-types/bb-plugin-sdk-app.d.ts:1678-1714, 1727-1728`). It does not expose a whole-draft snapshot/restore method. The current path therefore covers text, not an exact arbitrary structured draft snapshot.
- Stage/clear is reflected in a separate BB row-id projection (`src/revert-projection.ts:21-81`; `server.ts:1720-1769`). When `revertState` later reports no active provider marker, the server promotes staged rows into committed projection (`server.ts:669-678`). This projection transition does not itself call OpenCode's commit endpoint.

## Exact v2 server contract and upstream semantics

- Upstream OpenCode `dev` defines `Revert.State` as `{ messageID, partID?, snapshot?, diff?, files? }`; each file diff contains path/status/additions/deletions/patch (`packages/schema/src/revert.ts`, [source](https://github.com/anomalyco/opencode/blob/dev/packages/schema/src/revert.ts)).
- Protocol `POST /api/session/:sessionID/revert/stage` accepts `{ messageID, files? }` and succeeds with `{ data: Revert.State }`; `clear` and `commit` are POSTs with no payload and `204 No Content` success (`packages/protocol/src/groups/session.ts:256-289`, [source](https://github.com/anomalyco/opencode/blob/dev/packages/protocol/src/groups/session.ts)).
- Core `stage` captures the pre-revert snapshot, plans file restores from assistant-message snapshots, restores the selected boundary, then publishes Staged; `clear` restores the captured pre-stage files and publishes Cleared; `commit` publishes Committed (`packages/core/src/session/revert.ts`, [source](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/revert.ts)). The endpoint handlers wrap stage's result in `{data}` and clear/commit return no content (`packages/server/src/handlers/session.ts`, [source](https://github.com/anomalyco/opencode/blob/dev/packages/server/src/handlers/session.ts)).
- The server enables Basic auth only when `OPENCODE_SERVER_PASSWORD` is set. The configured username is `OPENCODE_SERVER_USERNAME`, defaulting to `opencode`; its auth helper builds `Authorization: Basic base64(username:password)` (`packages/server/src/auth.ts:20-62` and `packages/server/src/middleware/authorization.ts:9-55`, [auth](https://github.com/anomalyco/opencode/blob/dev/packages/server/src/auth.ts), [middleware](https://github.com/anomalyco/opencode/blob/dev/packages/server/src/middleware/authorization.ts)). The ticket reports live 2.0.18 endpoint probes; this research did not independently probe a local server.
