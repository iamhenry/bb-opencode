# External signal

- **OpenCode v2 `dev` API has distinct reversible lifecycle calls.** `POST /api/session/:sessionID/revert/stage` accepts `{ messageID, files? }` and returns `{ data: Revert.State }`; `clear` and `commit` take no JSON body and return `204`. `Revert.State` holds `messageID`, optional `partID`, snapshot/diff, and file diffs. Sources: [session protocol](https://github.com/anomalyco/opencode/blob/dev/packages/protocol/src/groups/session.ts#L256-L289), [revert schema](https://github.com/anomalyco/opencode/blob/dev/packages/schema/src/revert.ts). **What this changes:** plugin stage/clear are already present; add explicit commit separately and do not treat clear as commit.
- **Stage is snapshot-based, not a git reset.** Core stage computes file restores from later assistant message snapshots and captures the original workspace snapshot; clear restores that original snapshot; commit publishes the committed boundary (`[core revert](https://github.com/anomalyco/opencode/blob/dev/packages/core/src/session/revert.ts)`). The server handler wraps the staged state in `{data}` and returns no content for clear/commit (`[handler](https://github.com/anomalyco/opencode/blob/dev/packages/server/src/handlers/session.ts)`). **What this changes:** use provider snapshot semantics; do not add plugin-side git mutation.
- **Auth is optional Basic auth, controlled by server environment.** If `OPENCODE_SERVER_PASSWORD` is nonempty, authorization is required; username is `OPENCODE_SERVER_USERNAME` or default `opencode`, with `Authorization: Basic base64(username:password)` (`[auth config/helper](https://github.com/anomalyco/opencode/blob/dev/packages/server/src/auth.ts#L20-L62), [middleware](https://github.com/anomalyco/opencode/blob/dev/packages/server/src/middleware/authorization.ts#L9-L55)`). The ticket reports unauthenticated 401 and 2.0.18 live endpoint checks; this intake did not issue local requests.
- **OpenChamber implements the relevant UX directly against OpenCode.** Its `revertToMessage` stops a busy session, restores prompt text/files/context, stages descendant sessions, then stages the parent; descendant cutoff moves back to the child start when the target carries that child run. Its dock offers Clear and Commit (`[session actions](https://github.com/openchamber/openchamber/blob/main/packages/ui/src/sync/session-actions.ts#L443-L518), [stage flow](https://github.com/openchamber/openchamber/blob/main/packages/ui/src/sync/session-actions.ts#L2340-L2473), [dock](https://github.com/openchamber/openchamber/blob/main/packages/ui/src/components/chat/composer/ui/RevertedMessageDock.tsx#L1-L180)`). **What this changes:** adapt the flow, but recurse/stop descendants and preserve action ordering; don't copy its app-specific stores.
- **Native user-only behavior does not imply BB slot support.** OpenCode routes `actions` to `UserMessageDisplay` but not `AssistantMessageDisplay` (`[message part](https://github.com/anomalyco/opencode/blob/dev/packages/session-ui/src/components/message-part.tsx#L936-L981)`). OpenChamber passes `onRevert` only in the user branch (`[ChatMessage](https://github.com/openchamber/openchamber/blob/main/packages/ui/src/components/chat/ChatMessage.tsx#L782-L894)`). **What this changes:** user-only visibility is a real product requirement, but local BB support must be checked independently.
- **BB SDK distinction is a hard compatibility constraint.** In the pinned installed SDK 0.4.16, global `PluginMessageActionRegistration` has no role filter, while component-scoped `ThreadChatMessageAction` has `roles?: ["user"|"assistant"]` ([upstream app contract](https://github.com/get-bb/bb/blob/main/packages/plugin-sdk/src/app-contract.ts#L1740-L1757), [ThreadChat action](https://github.com/get-bb/bb/blob/main/packages/plugin-sdk/src/app-contract.ts#L2593-L2615)). `ArrowTurnBackward` is in the BB HugeIcons extended icon list ([icon registry](https://github.com/get-bb/bb/blob/main/packages/shared-ui/src/components/ui/icon-registry.ts#L4-L20)). **What this changes:** change the icon locally; request/add a global action `roles` filter upstream before claiming assistant rows no longer show the button. Do not use undocumented DOM surgery as equivalent support.
